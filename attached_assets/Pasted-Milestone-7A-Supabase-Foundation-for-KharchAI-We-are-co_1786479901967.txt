STEP 4 — INITIAL DATABASE SCHEMA
==================================================

Create the minimum database schema needed for the NEXT milestone:

A financial_records table.

The schema should be designed around the existing Universal Financial Record rather than around receipt-specific fields.

It must be capable of storing records from:

- receipt
- utility_bill
- wallet_screenshot

At minimum, establish fields for the normalized financial record identity and core financial information, while preserving document-specific information in a structured JSON/JSONB field where appropriate.

The design should support:

- record ID
- document type
- source
- transaction date where applicable
- merchant/provider where applicable
- amount
- currency
- category where applicable
- normalized items where applicable
- metadata
- confidence
- parser version
- created timestamp
- updated timestamp

Do NOT duplicate dozens of receipt-specific columns.

The database should remain compatible with the UFR architecture.

If the existing UFR has fields that should be persisted, inspect the actual implementation and map them appropriately.
